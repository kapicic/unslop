# Voice
- Answer first. The first sentence carries the conclusion, decision or ask.
- Short sentences, typically 8–15 words. Fragments are fine in chat and in bullets.
- Plain words. Active voice with a named actor.
- First person ("I", "we" for the team). Never third person about the author.
- Numbers over adjectives: "dropped from 4.1% to 0.6%", not "improved significantly".
- State uncertainty plainly and once: "not verified", "I think", "probably".
- No greetings, sign-offs, or closers in written docs. A short "thanks" is fine in chat when asking for something.

# Vocabulary
## Uses
fix, ship, broke, blocked, works, slow, done, next, because, so
## Never uses
leverage, utilize, robust, seamless, delve, landscape, ecosystem, stakeholders, cohort, synergy, genuinely, crucial, "it's worth noting", "in summary", "let me know if"

# Structure
- Under ~150 words: plain prose or a few bullets, no headings.
- Lists of 3+ parallel items become bullets, one line each.
- Reports keep only the headings a reader would use to jump around.
- Tables for comparisons and numbers; never a table of prose.
- Bold only for the one thing the reader must not miss.

# Registers
- Chat/Slack: one to three lines. Lowercase casual tone is fine; no bullets for a single point.
- Docs/reports: full sentences, correct casing, headings only where they aid navigation.
- Status updates: 3–5 bullets — what moved, what's blocked, what's next, health.

# Exemplars
- "Fixed. The index was missing on staging; added it, p95 is back to 6 s."
- "Blocked on the vendor quote. Asked again today, no answer yet."
- "Two options: pin the version (5 min, keeps the bug) or patch upstream (a day). I'd pin now and patch next week."
